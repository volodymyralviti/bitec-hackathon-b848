# Навчальні сценарії — Stage 04 / EDS-011–014

Два авторські українськомовні сценарії за мотивами CIDS. Обидва мають
`schemaVersion: "1"`, `version: "1.0.0"`, `publicationStatus: "draft"`,
`contentReview: {status: "draft", demoOnly: true, aiAssisted: true}`.
Це матеріал для content review, а не експертно схвалена публікація чи юридична порада.
API на першому запуску копіює лише явний `index.json` у demo-only каталог;
публічна копія має `publicationStatus=demo`, а ці оригінали залишаються draft.
Це технічний показ демо, без зміни людського review чи перевірки джерел.

| Файл | Сюжет | Вузли | Decision nodes | Choices | Endings | Повні маршрути | Рішень на маршрут |
|---|---|---:|---:|---:|---:|---:|---:|
| [urgent-supply.json](scenarios/urgent-supply.json) | Резервне живлення відкритих занять центру підготовки цивільних фахівців сектору безпеки й оборони | 12 | 7 | 14 | 4 | 8 | рівно 3 |
| [truth-under-pressure.json](scenarios/truth-under-pressure.json) | Професійна порада установі сектору безпеки й оборони про доступність відкритої програми доброчесності для цивільних працівників | 12 | 7 | 14 | 4 | 8 | рівно 3 |

У кожному сценарії є один вступний narrative node, сім decision nodes у трьох
послідовних шарах (1 → 2 → 4), чотири ending nodes і сім delayed events.
Кожне рішення має два варіанти, кожен варіант — immediate effects і пояснення
користі та ризику. Вибір змінює наступний контекст або завершення. Немає умов,
скриптів, випадковості, персональних даних чи реальних операційних відомостей.

Карта всіх маршрутів із choice IDs та очікуваними моментами delayed triggers:
[постачання](qa/urgent-supply.routes.json), [професійна порада](qa/truth-under-pressure.routes.json).
Це статичні докази, не збережені результати учасників і не виконання engine.
Нотатки для викладача: [постачання](teaching-notes/urgent-supply.md),
[професійна порада](teaching-notes/truth-under-pressure.md).

## Джерела та межі перевірки

У checkout не знайдено `task.pdf` та оригінального українського PDF CIDS.
Першоджерела безпосередньо **не прочитано**. Використано надане завдання команди,
`docs/PROJECT_CONTEXT.md`, `docs/SOURCE_TRACEABILITY.md` та фактичний Stage 02 DSL.
Дати, сторінки й описи CIDS наведено як бібліографічні орієнтири з цього контексту,
без заяви про незалежну перевірку.

У кожному JSON є локальний реєстр трьох джерел:

| sourceId | Тип і локатор | Статус |
|---|---|---|
| `cids-case` | CIDS, «Посібник з вирішення дилем на робочому місці у державному секторі», українське видання, за контекстом — січень 2025; орієнтир `11388-CIDS-rapport-2-2024-UKR-skjerm.pdf`. №16: PDF с.14 / друкована с.10; №1: PDF с.13 / друкована с.9 | `unverified`, revision/versionAsOf/verifiedAt = null |
| `cids-method` | Той самий бібліографічний орієнтир, PDF с.11–12 / друковані с.7–8: шість кроків і п’ять перевірок | `unverified`, revision/versionAsOf/verifiedAt = null |
| `editorial-model` | JSON відповідного сценарію та його teaching notes, авторська модель 1.0.0 | `unverified`, versionAsOf/verifiedAt = null |

Атрибуція: Centre for Integrity in the Defence Sector (CIDS), Oslo. Авторські
адаптації створено за участю Codex 2026-11-19; це дата підготовки контенту,
**не дата перевірки джерел**. Немає фактичного людського reviewer, доказу схвалення
чи завершених `reviewedAt`, `reviewerRole`, `evidenceRef`.

За уточненням команди, оригінальний CIDS №16 описує комунікаційне обладнання та
запчастини, бюджет, технічні вимоги, ризик неформального доступу до інформації
**та термінову потребу в генераторах для зарядки батарей**. Отже, попередній опис,
який відділяв будь-яку згадку генераторів від оригіналу, був неповним.
Поточний сюжет із резервним живленням відкритого навчання — **авторська адаптація**,
а не переказ усього кейсу чи цитата з CIDS. Уточнення надано командою;
воно не означає незалежного прочитання PDF і не змінює `unverified`.
CIDS №1 задає конфлікт професійної консультації з очікуваннями політичного
керівництва; освітня програма й усі наступні події — авторська адаптація.
Великі уривки посібника не копіюються. Перед зовнішнім використанням команда
має перевірити умови атрибуції, повідомлення CIDS і некомерційного відтворення
(орієнтир із контексту: PDF с.19 / друкована с.15).

Українські нормативні акти не додавались: перевірених редакцій і застосовності
немає. Усі choice `legalStatus` — `uncertain`; у вступі та кожному debrief є
видиме застереження `unverified`. Жоден варіант не дозволяє обхід процедур,
фальсифікацію даних або розголошення захищених відомостей. Рекомендації умовні;
допустимість і повноваження потрібно перевіряти окремо. CIDS не замінює право України.

## Відповідність сектору безпеки й оборони

Вступи й summaries обох JSON прямо визначають аудиторію та інституційний контекст:
цивільні фахівці сектору, підготовка з доброчесності, підзвітність управління
ресурсами й незалежність професійної поради в умовах очікувань керівництва.
Перший кейс тренує аргументацію в забезпеченні відкритого навчання, другий —
підготовку доказового висновку щодо його доступності. Зв’язок із сектором є
управлінським і освітнім; тактична підготовка, оцінка спроможностей, реальні
підрозділи, закупівлі, місця, номенклатура та службові документи не додаються.
За авторським оглядом цього достатньо для безпечного вступного тренінгу;
профільне педагогічне review має підтвердити релевантність для конкретної аудиторії.

## Як перевірити

З кореня репозиторію, без зміни package manifests чи scripts:

```sh
# Node.js 22.22.3 та pnpm 10.0.0; engine-strict залишається увімкненим.
pnpm install --frozen-lockfile
pnpm --filter @eds/scenario-schema build
node content/qa/validate.mjs
node --test content/qa/content.test.mjs
```

**Основний gate — публічний `validateScenario` з `@eds/scenario-schema`.** QA
резолвить self-reference пакета через його `package.json` і public CJS exports.
Внутрішні `src`/`dist` subpaths не імпортуються. Потрібна вже підготовлена збірка
пакета та його залежності; два попередні кроки готують їх, самі QA scripts
не встановлюють залежностей і не перебудовують schema.
Перевіряються також `validateScenarioJson`, прямий graph validator, збереження
трьох очікуваних `SOURCE_UNVERIFIED` warnings та відсутність graph warnings/errors.
Негативні тести змінюють лише об’єкти в пам’яті: missing target, короткий шлях,
цикл, один choice, неможливий counter, повторний delayed ID, хибна правова
певність, спроба production publication і некоректний JSON.

Додаткова перевірка для маленьких графів перебирає всі маршрути, перевіряє
досяжність усіх вузлів/ending, мінімальну довжину, унікальність delayed IDs,
immediate effects і статичну досяжність обох типів triggers. Це **не заміна DSL
validator**. Для обох сценаріїв усі заплановані події досягають тригера на кожному
продовженні після вибору, що їх планує; branch-dependent відкинутих подій немає.

Якщо schema build ще немає, доступний лише додатковий режим:

```sh
node content/qa/validate.mjs --inspect-only
```

Він явно пише `schema/graph acceptance gate NOT RUN` і не оголошує Stage 04 PASS.
Перегенерація карт після **контентних** змін:

```sh
node content/qa/validate.mjs --write-maps
```

Для статичної карти без доступного validator можна додати `--inspect-only`;
це не підвищує статус валідації. `routes.mjs` не застосовує deltas, не створює
simulation state і не виконує delayed events: він лише знаходить їхні очікувані
топологічні точки за контрактом Stage 02. Runtime, точно-один-раз та UI належать Stage 03/05.

Результати цього checkout і acceptance checklist: [qa/REVIEW.md](qa/REVIEW.md).

## Методика проведення й human review

Послідовність обговорення: визначити дилему → залучити ресурси → запропонувати
альтернативи → оцінити ймовірність і тяжкість наслідків → обґрунтувати вибір →
переоцінити за новими фактами. Кожен debrief містить питання про правову
допустимість, професійні стандарти, інтуїцію, публічність і рольову модель.

Цифри — умовні авторські зміни в чотирьох вимірах наслідків: `transparency`,
`fairness`, `trust`, `effectiveness`. Вони не є ймовірностями, емпіричними оцінками,
моральним балом, рейтингом чи підставою кадрового рішення. Не сумуйте їх у
«добропорядність», не порівнюйте людей і не передавайте індивідуальні шляхи
викладачу/командиру. Для заняття обговорюйте підстави, стейкхолдерів і альтернативи.

До використання поза демо потрібні звірка PDF/атрибуції, юридична перевірка
допустимості дій і каналів, технічне та педагогічне review, перевірка ваг і
правдоподібності наслідків. Конкретні питання є в teaching notes. Статуси джерел
чи review не можна підвищувати лише тому, що JSON пройшов автоматичний тест.
