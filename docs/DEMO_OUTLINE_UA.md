# Demo outline — план для команди, не запис готового виступу

## Підготовка

Виконати install/build/checks з README. Запустити API та Angular, перевірити
`http://localhost:4200/api/health`. Для rehearsal використати **новий**
`SCENARIO_DATA_FILE` у тимчасовому каталозі; не видаляти робоче сховище Studio.
Якщо потрібен Studio, задати випадковий `AUTHOR_KEY` лише в середовищі API,
не друкувати його на екрані й не записувати у відео. Reviewer лишити вимкненим.

Відкрити каталог, `/studio`, `/classroom/host` і три окремі participant contexts.
Підготувати кімнату та приєднання, але відкрити раунд наживо. Для приховування
малих груп можна мати другу disposable кімнату з двома учасниками. Не підміняти
голоси hardcoded картинками; synthetic учасників прямо назвати тестовими.
На одному ноутбуці використовуються localhost URL; інші пристрої потребують
погодженого LAN/HTTPS/proxy налаштування. Це не автоматично offline classroom.

## Живий walkthrough — ціль 4 хв 40 с

| Час | Дія | Що пояснити |
|---|---|---|
| 0:00–0:25 | Каталог двох кейсів | «Тренуємо міркування, а не визначаємо моральні якості». Demo-only, AI-assisted, без експертного review. |
| 0:25–1:35 | `urgent-supply`: вступ → `common-brief` → `shared-questions` → `recommend-minimum` | На кожному рішенні вибір і підтвердження; альтернативи мають користь і ціну. Після другого рішення з’являється `supply-common-record`, після третього `supply-brief-rework`. |
| 1:35–2:05 | Ending → debrief → джерела | Короткий/довгий горизонт, чотири метрики `3 / 2 / 0 / 1`, жодного загального морального балу. Unverified означає потребу людської перевірки. |
| 2:05–3:10 | Host відкриває раунд; три тестові учасники голосують; host закриває | До close результатів немає. Після close — лише агрегат. Ведучий сам обирає спільну гілку. Показати suppression другої двоголосої кімнати. |
| 3:10–4:15 | Studio: нова форма/збережена приватна чернетка → редагування → validation → export → preview | JSON поза кодом, три послідовні рішення. Для короткого демо preview починається зі вступу; повний прохід уже показано в solo. Жодного натискання «expert-approved». |
| 4:15–4:40 | Повернення до каталогу; пояснити архітектуру | Той самий engine у solo/preview/classroom. Немає особистих звітів. Людське review, політика ШІ й фінальна подача — наступні рішення команди. |

Коротка версія на 2–3 хв: скоротити усні пояснення, показати один classroom-раунд,
одне поле Studio та preview; не пропускати три solo-рішення й delayed effect.
Це часовий план: виступ із командою ще потрібно відрепетирувати й заміряти.

Другий контрольний solo-маршрут: `truth-under-pressure` → `peer-window` →
`interim-options` → `test-access` → `conditional-pilot`; фінальні метрики
`4 / −1 / 1 / 0`. Використати як запасний кейс, не видавати його за юридичну пораду.

## Відео outline — ціль 2 хв 50 с, максимум 3 хв

| Час | Кадр/запис |
|---|---|
| 0:00–0:15 | Назва, проблема, демо-статус; жодних ідентифікаторів реальних слухачів. |
| 0:15–1:15 | Реальний solo: вступ, три підтверджені рішення, негайні й відкладені наслідки, debrief. |
| 1:15–1:45 | Host + три synthetic participant contexts; відкрите голосування без counts, close → aggregate; короткий suppressed result. |
| 1:45–2:25 | Studio: відредагувати поле, перевірити, експортувати, відкрити приватний preview. |
| 2:25–2:50 | Джерела unverified, AI usage, відсутність індивідуальних звітів, людське review та обмеження. |

Записати лише вигадані дані; приховати пароль, terminal env, особисті вкладки
й повідомлення. Не монтувати тестовий reviewer stub як реальне схвалення.
За проблем мережі показати чесний error/retry і локально перевірений solo,
не заявляти про успішний classroom-раунд, якого не було.

## Команда завершує

Підтвердити актуальні правила/рік/дедлайн у організатора, перевірити джерела й
умови CIDS, відрепетирувати виступ, записати та перевірити тривалість відео.
Фінальні слайди/PDF, публічний репозиторій і подача залишаються відповідальністю
команди. У Stage 08 фінальний slideshow/PDF і реальне розгортання не створювались.
