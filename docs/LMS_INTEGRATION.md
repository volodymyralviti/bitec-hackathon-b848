# Moodle / Дія.Освіта — межа майбутньої інтеграції

Це архітектурна можливість, а не реалізований чи сертифікований LMS adapter.
SCORM package, xAPI/LRS, Moodle plugin та API-з’єднання з Дія.Освіта відсутні.
Вимоги конкретної платформи потрібно одержати й погодити окремо; сумісність із
її чинною специфікацією не заявляється.

## Повторно використовувані частини

- JSON DSL v1 має `id/version/language`, review/AI/source metadata й повний граф.
- `@eds/scenario-schema` перевіряє імпорт до початку проходження.
- Pure `@eds/scenario-engine` не залежить від Angular, NestJS або LMS.
- Immutable публічна версія дає сталі посилання на контент і джерела.
- Participant UI працює без learner account; авторинг і review захищені окремо.

Найменший майбутній pilot — посилання з навчального курсу на публічний каталог
або погоджене embedded-відображення. Це ще потребує review origin/CSP, доступності,
версій контенту, мережевих логів і того, які ідентифікатори платформа передає.
Сам факт входу користувача в LMS може створювати зовнішній запис доступу;
застосунок не може називати такий запис анонімним.

## Privacy contract перед будь-яким adapter

Не передавати в LRS/gradebook імена, learner IDs, індивідуальні choices, результати,
маршрути, голоси чи моральний score. Не додавати персональну аналітику заради
формальної підтримки xAPI/SCORM. Поточний симулятор не має згоди або схеми
зберігання таких відомостей. Потреба платформи в ідентифікованому actor чи
персональній оцінці — конфлікт, що вимагає нового людського рішення, не прихована
мапа метрик у gradebook. Агрегати classroom не стають дозволеним звітом про особу.

Якщо погоджено обмін `postMessage`, потрібні явні allowlisted origins, мінімальні
повідомлення, валідація версії/структури й відсутність secrets у URL. Якщо потрібна
пакетна доставка, включати лише явно публічні reviewed/demo матеріали, metadata
та ліцензійні умови; приватні Studio draft і host capabilities не експортувати.
Жодний із цих транспортів зараз не реалізований.

## Окреме погодження команди

Одержати контракт платформи й AI/privacy policy, визначити безпечний обсяг даних,
перевірити умови контенту, погодити access/logging, написати негативні тести
ідентифікаторів/неавторизованих origins і тільки потім реалізовувати adapter.
Відсутність LMS adapter не блокує локальний MVP і не є прихованою частиною Stage 08.
